# 07: บันทึกการทดลองและข้อค้นพบลงเอกสาร

**What to build:** README เป็นเอกสารหลักของโปรเจคและเป็นที่ที่คนอ่านก่อนอย่างอื่น ต้องอธิบาย
การทดลองนี้ให้ครบพอที่คนอื่นทำซ้ำได้ และให้คนที่มาแก้โค้ดต่อเข้าใจว่าทำไมถึงตัดสินใจแบบนี้

สิ่งที่ต้องมี:

- คำถามของการทดลองและคำตอบที่วัดได้ พร้อมความไม่แน่นอน — ถ้าผลออกมาว่าไม่ช่วย ให้รายงาน
  ตามจริงพร้อมเหตุผลที่วิเคราะห์ได้ ตามแบบที่ README ทำอยู่แล้วกับข้อค้นพบเรื่อง LSTM แพ้
  logistic regression
- **เหตุผลที่เลือก cadence 12 ชม. ไม่ใช่ 1 ชม.** — ไม่งั้นคนที่มาทีหลังจะไปแก้กลับด้วยความหวังดี
  แล้วเจอว่าต้องดาวน์โหลดสองสัปดาห์
- ขั้นตอนรันทั้งหมดเรียงตามลำดับ พร้อมเวลาที่ใช้จริงและพื้นที่ดิสก์ที่กิน
- คำเตือนว่าโมเดลของงานศึกษาอยู่คู่กับโมเดลเดิม ไม่ได้แทนที่ และหน้าเว็บยังเสิร์ฟตัวเดิม

**แก้ของที่ล้าสมัยไปพร้อมกัน** (พบระหว่างสำรวจโค้ด ไม่เกี่ยวกับงานนี้โดยตรงแต่อยู่หน้าเดียวกัน):

- หัวข้อ Segmentation ยังเขียนว่า U-Net "ยังไม่ได้เทรน" ทั้งที่เทรนเสร็จแล้ว — Dice 0.916 / IoU 0.855 บน test
- ตารางผลการทดลองและตารางการแบ่งข้อมูลอ้างตัวเลข test 9,886 sample / 37 positive ซึ่งเป็น
  ตัวเลขก่อนเพิ่มหน้าต่าง case study — ชุดข้อมูลบนดิสก์ตอนนี้คือ 13,935 / 420 ครอบคลุมถึง พ.ค. 2024
