# 01: เคลียร์เทสต์ที่พังค้างให้ชุดเทสต์กลับมาเขียว

**What to build:** ชุดเทสต์ของ backend ผ่านทั้งหมด เพื่อให้งานที่เหลือในชุดนี้มีฐานอ้างอิงว่าอะไรพัง
เพราะงานใหม่ ตอนนี้มีเทสต์แดงค้างอยู่สองตัวซึ่งไม่เกี่ยวกับงานเปรียบเทียบชุด feature เลย
ถ้าปล่อยไว้ ทุกใบต่อจากนี้จะเริ่มจากชุดเทสต์ที่แดงอยู่แล้ว

**นี่คือ prefactor** ไม่ใช่ฟีเจอร์ — ทำให้การเปลี่ยนแปลงง่ายก่อน แล้วค่อยเปลี่ยน

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] เทสต์ที่ยืนยันว่ามีหน้าเว็บถูกเสิร์ฟที่ราก ถูกแก้ให้ยืนยัน**สัญญาปัจจุบัน**แทน: backend เป็น
      API ล้วนหลังแยก container แล้ว คำขอที่รากจึงต้องได้ 404 — เปลี่ยนชื่อเป็น
      `test_root_is_not_served_by_backend` ให้สะท้อนสิ่งที่มันตรวจจริง (`backend/tests/test_app_smoke.py`)
- [x] เทสต์ลำดับของ track ใน intensity-series วินิจฉัยแล้วว่าเป็น**บั๊กจริง**: `label` ของแต่ละ
      track ใช้ `track.track_id` (ตัวนับภายในที่โตขึ้นเรื่อยๆ ตลอดการไล่เฟรม — ที่ cadence
      รายสัปดาห์การจับคู่ AR ข้ามเฟรมมักพลาด จึงสร้าง track ใหม่บ่อยจน track_id ของ AR ที่ใหญ่
      ที่สุดอาจเป็นเลขหลักร้อย) แทนที่จะใช้ `rank` (อันดับตามพื้นที่ในคำตอบนั้น) ตามที่ schema
      ตั้งใจไว้เอง (`label` มี docstring ว่า `'ชื่อที่แสดงบนกราฟ เช่น "AR 3"'`) — แก้ให้ label
      ใช้ rank เสมอ ส่วน track_id ยังส่งแยกเป็น field ของตัวเองสำหรับใช้อ้างอิงที่ต้องการความ
      คงที่ (`backend/app/routers/segment.py`)
- [x] พบและแก้เทสต์แดงเพิ่มอีกหนึ่งตัวระหว่างรันชุดเต็ม — ไม่อยู่ในสองตัวที่ตั้งเป้าไว้แต่แรก
      แต่กระทบเกณฑ์ "ชุดเทสต์ทั้งหมดผ่าน": `test_initial_predictions_are_mostly_negative` ใน
      `backend/tests/test_models.py` สุ่ม weight init และ input โดยไม่ seed ทำให้ล้มเป็น
      ครั้งคราวโดยไม่มีอะไรเปลี่ยนในโค้ดจริง (วัดจริง 30 seed: ล้ม 1/30) — seed ทั้งการสร้าง
      โมเดลและ input ให้ deterministic แทน ยืนยันด้วยการรันซ้ำ 6 ครั้งติดกันแล้วผ่านทุกครั้ง
- [x] ชุดเทสต์ทั้งหมดผ่าน ยกเว้นที่ข้ามอย่างตั้งใจ — 312 passed, 1 skipped รันซ้ำ 4 รอบติดกัน
      ได้ผลเดิมทุกครั้ง (ยืนยันว่าไม่ใช่ความบังเอิญ)
- [x] ไม่มี endpoint ใดที่หน้าเว็บใช้อยู่เปลี่ยนพฤติกรรม — การแก้ label ใช้ path เดียวกับที่
      `frontend/src/components/Dashboard/ExtractionCard.jsx` ใช้อยู่แล้ว (`track.label` สำหรับ
      แสดงผล, `track.track_id` สำหรับอ้างอิง) ไม่มี field ใหม่หรือ field ที่หายไป
